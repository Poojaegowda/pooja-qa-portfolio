# 📚 Manual Testing Concepts

## 1. What is Software Testing?

Software Testing is the process of evaluating a software application to verify that it meets the specified requirements and to identify defects.

---

## 2. Why is Software Testing Important?

Software Testing helps to:

- Identify defects early
- Verify that requirements are met
- Improve software quality
- Reduce risks
- Improve customer satisfaction

---

## 3. SDLC

SDLC stands for **Software Development Life Cycle**.

### Common Phases:

1. Requirement Analysis
2. Planning
3. Design
4. Development
5. Testing
6. Deployment
7. Maintenance

---

## 4. STLC

STLC stands for **Software Testing Life Cycle**.

### Phases:

1. Requirement Analysis
2. Test Planning
3. Test Case Design
4. Test Environment Setup
5. Test Execution
6. Defect Reporting
7. Test Closure

---

## 5. Verification vs Validation

### Verification

Verification checks whether the product is being built correctly.

**Example:** Reviewing requirements, design documents, and test cases.

### Validation

Validation checks whether the correct product has been built.

**Example:** Executing test cases on the application.

---

## 6. QA vs QC vs Testing

### Quality Assurance (QA)

QA focuses on improving processes to prevent defects.

### Quality Control (QC)

QC focuses on identifying defects in the product.

### Software Testing

Testing involves evaluating the application to find defects and verify requirements.

---

## 7. Types of Testing

### Functional Testing

Verifies whether the application functions according to the requirements.

### Non-Functional Testing

Tests characteristics such as:

- Performance
- Usability
- Security
- Compatibility

---

## 8. Smoke Testing

Smoke Testing is performed to verify that the basic and critical features of an application are working.

**Example:** Checking whether the application launches and users can log in.

---

## 9. Sanity Testing

Sanity Testing is performed to verify specific changes or bug fixes.

**Example:** Testing a fixed login issue.

---

## 10. Regression Testing

Regression Testing verifies that new changes have not affected existing functionality.

---

## 11. Retesting

Retesting means testing a previously failed test case after the defect has been fixed.

---

## 12. Severity vs Priority

### Severity

Severity indicates the impact of a defect on the application.

### Priority

Priority indicates how quickly the defect should be fixed.
